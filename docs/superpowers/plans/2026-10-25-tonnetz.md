# Tonnetz Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** v1 and v2 built on `tonnetz-expansion` (2026-10-25). The v3 items are open. First draft by Sonnet; reviewed and redesigned by Opus with Mark's decisions.
**Spec:** `docs/superpowers/specs/2026-10-25-tonnetz-design.md` (decision log updated alongside this plan)
**Branch:** `tonnetz-expansion`

**Goal:** A Tonnetz element: a flat card (v1) and an immersive phantom.land-style 3D world opened from it (v2), with polish and history (v3).

**Architecture:** A pure theory core (`lib/theory/tonnetz.ts`) feeds both views. The card is SVG, following the PitchAxisCard pattern. The 3D world is a lazily imported React Three Fiber overlay. It draws the whole lattice (fills, edges, seams, nodes, labels, highlights) procedurally in one fragment shader, on one tiled mesh, and drives all motion from one frame clock with no React state per frame.

**Tech stack added (v2):** `three`, `@react-three/fiber` v9. **Dropped from the spec's list:** `@react-three/drei` (no troika text: labels come from a glyph atlas drawn with the app's own fonts) and `postprocessing` (glow is computed in the shader, which also works in the light theme, where bloom looks wrong). GSAP is already installed and is used only for DOM transitions.

## Decisions (Mark, 2026-10-25)

- **D1 (revised): endless curved plane plus roll-up.** The main 3D view is phantom.land's own technique: a front-facing endless plane, panned in 2D with momentum, its edges bent away by a vertex curvature. That plane *is* the torus unrolled (its universal cover), so seams and tinted copies show the fold. Pulling back (scroll or pinch out) rolls one copy up into the literal torus, seen from outside, with a marker for where you are. The **Wraps** option is dropped.
- **D3: fixed world.** The plane never rotates. Major triangles point up and minor ones point down, everywhere.
- **D4: move bar on the card too.** A compact P L R N S H bar on the card, acting on the selected triad. Typing the letters performs the move on both the card (when it is the only selection) and in 3D.
- **Card scope:** the card shows the flat lattice with one copy of the torus at full strength and the repeat around it fading out. It is not 3D.

## Review of the first draft (why the 3D design changed)

1. **The literal torus can't be fixed with Wraps.** With constant triangle size, the large loop holds `4w` cells and the small loop `3w`, so `R / r = 4/3` at every wrap count. That is nearly a horn torus: inner-side cells come out about 7× smaller than outer-side ones, and from inside the tube the wall curves out of view about one cell ahead. Wraps only scales the same shape up.
2. **phantom.land is not a tunnel.** Checked live on 2026-10-25: it is a flat, front-facing tile grid panned in 2D, wrapping endlessly, with barrel curvature at the edges. Content always faces the viewer, which is what makes it calm and readable. A camera inside a tube puts most of the content at grazing angles and labels upside down overhead.
3. **The draft's motion design would jitter.** It drove the same angles from both a `useFrame` integrator and GSAP timelines, which means two clocks (GSAP's ticker and R3F's rAF) and two writers. The fix is one clock and one owner. All in-scene motion (drag, inertia, key steps, snapping, move travel) is a single analytic critically damped spring plus an exponential decay, advanced in `useFrame`. GSAP never touches scene values.
4. **"Snap to nearest step" kills throws** if "nearest" means nearest at release. The fix is to project the inertial rest point (`p + v / λ`), snap to the step nearest *that*, and hand the spring the release velocity so the hand-off is seamless. This is iOS-style snap scrolling.
5. **Drag must be direct manipulation.** The lattice point under the pointer stays under the pointer (world units per pixel derived from the camera), not an angle-per-pixel gain.
6. **Global shortcuts collide.** `CanvasApp` uses ↑/↓ (transpose or page switch), ←/→ and `R`; `Viewport` uses Space to pan. The overlay swallows keys in a window capture-phase listener. ↑/↓ transpose must include `tonnetz` (`CanvasApp.tsx:163`).
7. **Text quality.** drei/troika needs a font file URL, and `next/font` hashes it, so the 3D labels would not match the app's typography. Only 36 strings ever appear (12 notes and 24 chords), so draw them once to a canvas atlas with the loaded `--font-display` / `--font-body` faces and sample it in the shader.
8. **Colours must match the card.** Read tokens through a probe element (the browser resolves `var()` and `color-mix()` to `rgb()`), feed them through `THREE.Color.setStyle` (sRGB to linear), and end the shader with `colorspace_fragment`. Re-read on any `data-theme` / `data-surfaces` change (MutationObserver on `<html>`).
9. **Focus vs camera.** Focus is a **triad**, not a position. Its *rendered* position is the copy nearest the camera, so after panning away, arrow keys continue from what you are looking at. This is also the spec's "the copy under the camera brightest".
10. **Arrow keys.** Every triangle has one horizontal edge (P), a left sloped edge and a right sloped edge. On an up (major) triangle: ← = R, → = L, ↓ = P. On a down (minor) triangle: ← = L, → = R, ↑ = P. The arrow with no edge (↑ on major, ↓ on minor) gives a small bump instead of moving.
11. **The `S` conflict.** Plain `S` pans the 3D world (WASD), so in 3D the Slide move is **Shift+S**. Shift+letter works for every move, and plain P L R N H also work. On the card all six letters are plain.
12. **v1 notes.** Voice-leading must stay inside a register window (C3–C5) or long progressions drift. Double-clicking a note also fires two clicks, so the note plays before the lattice recentres, which is acceptable. `INSTANT_KINDS` is duplicated in store and StubCard.

## Geometry reference

- Flat layout `(i, j)` = (fifths, major thirds): `pc = centre + 7i + 4j`. Screen basis `e_i = (1, 0)`, `e_j = (½, √3/2)`.
- **Up** triangle at `(i, j)`: corners `(i,j) (i+1,j) (i,j+1)`, major, root `pc(i,j)`. **Down** triangle at `(i, j)`: corners `(i+1,j) (i,j+1) (i+1,j+1)`, minor, root `pc(i, j+1)`.
- Neighbours: up `(i,j)`: ← down `(i−1,j)` (R), → down `(i,j)` (L), ↓ down `(i,j−1)` (P). Down `(i,j)`: ← up `(i,j)` (L), → up `(i+1,j)` (R), ↑ up `(i,j+1)` (P).
- Torus coordinates `u = i + j` (major-third steps, mod 3), `v = i` (minor-third steps, mod 4); `pc = centre + 4u + 3v`. Period vectors in `(i, j)`: `(0, 3)` and `(4, −4)`. One copy = 12 notes and 24 triangles.
- Every lattice edge lies on an integer line of `i`, `j` or `i + j`. Seams are the lines where `u ≡ 0 (mod 3)` or `v ≡ 0 (mod 4)`.
