## Findings from reading the code (these shape the plan)

1. **Four places list element kinds and must change together.** `INSTANT_KINDS` is duplicated in `src/lib/canvas-store/store.ts:109` and `src/components/canvas/elements/StubCard.tsx:46`; `encodeDoc`'s `serializable` filter and its type union are in `src/lib/url-state/codec.ts:95`; the render switch is in `src/components/canvas/CanvasApp.tsx` (~line 330). Missing any one fails silently (element won't spawn, won't persist, or won't render).
2. **`transposeElements` only handles scale / chord / harmony** (`store.ts:225`), and Pitch Axis is not transposable. The spec asks for Tonnetz transpose, so the store function needs a second branch (shift `centre` and `triad.root`), and the `pitched` predicate must include `tonnetz`. This is the first element with a numeric pitch class instead of a `NoteName`.
3. **The codec letter `t` is free.** Existing codes: `f o p r w s h c`. The decoder checks `code.length` per kind; the Tonnetz code is 7 chars and `triad1` uses base36 of `root*2+minor` (0–23, always one char). The spec's `'z'` sentinel is 35, outside 0–23, so it cannot collide.
4. **`playProgression(chords, {onStep, onDone}, stepMs)`** takes `number[][]` of MIDI-ish pitches and already handles voice crossfade via `takeOver`. Voice-led moves only need a helper that picks inversions; no playback changes.
5. **A simpler torus coordinate exists for 3D.** The spec's flat layout uses `(i fifths, j major thirds)`. For the torus, use `(u, v)` = (major-third steps, minor-third steps), pitch class `c + 4u + 3v`, with `u` mod 3 and `v` mod 4. By the Chinese remainder theorem this hits all 12 pitch classes exactly once, so the torus is a clean 3×4 grid. Conversion from the flat layout: `u = i + j`, `v = i`. Each cell `(u,v)` is a square split by the root–fifth diagonal: lower triangle = major triad on `pc(u,v)`, upper = minor triad on the same root. That diagonal is the **P** edge, which is why one cell holds one major and one minor and the 24 triangles each appear once.
6. **Arrow-key neighbours in the spec map onto P, L, R.** The horizontal edge of every triangle is its root–fifth edge, which is the **P** neighbour (↑ for a down-pointing triangle, ↓ for an up-pointing one). The two sloped edges are **L** and **R**. Which is left or right depends on triangle orientation, so derive it from geometry in code and pin it with a test rather than hard-coding.
7. **Direction labels in the spec's axis table describe lines, not directions.** The minor-third axis is the line through `(−1, +1)` in `(i,j)`, which draws up-left; ascending a minor third (+3) goes down-right on that line. No change needed; keep this in mind when writing hover highlights.
8. **Playback glow, glass nodes, themes.** `FractalScene.tsx` exports `GlassGradient`, which PitchAxisCard already reuses for node washes; `_lit.scss` holds the playback glow. Reuse both in the card. `lib/theme.ts` exposes the active theme; the 3D view must re-read tokens on theme change.

# Phase 1 (v1): Theory core + Tonnetz card

## Task 1.1: Theory core, triads and moves

**Files:**
- Create: `src/lib/theory/tonnetz.ts`, `src/lib/theory/tonnetz.test.ts`

- [ ] **Step 1: Failing tests.** Cover exactly the spec's invariants:
  - `TRIADS` has 24 entries in codec order `root * 2 + minor`; `TRIADS[0]` is C major, `TRIADS[1]` is C minor.
  - From C major: P → Cm, R → Am, L → Em, N → Fm, S → C♯m, H → G♯m (spelled A♭m in the spec; the app's `NOTE_NAMES` gives `G#m`).
  - Every move is an involution over all 24 triads.
  - Common-tone counts from C major: P 2, R 2, L 2, N 1, S 1, H 0.
  - `movePath` returns the triads passed through: length `steps + 1`, first = start, last = `applyMove` result.
  - `triadName({root:0,minor:false})` = `"C"`, `{root:9,minor:true}` = `"Am"`.
- [ ] **Step 2: Implement.**
  ```ts
  export interface Triad { root: number; minor: boolean }
  export const TRIADS: Triad[] = Array.from({ length: 24 }, (_, k) => ({ root: k >> 1, minor: (k & 1) === 1 }));
  export const triadIndex = (t: Triad) => t.root * 2 + (t.minor ? 1 : 0);

  const mod12 = (n: number) => ((n % 12) + 12) % 12;
  type Step = 'P' | 'L' | 'R';
  const STEP: Record<Step, (t: Triad) => Triad> = {
    P: (t) => ({ root: t.root, minor: !t.minor }),
    R: (t) => (t.minor ? { root: mod12(t.root + 3), minor: false } : { root: mod12(t.root - 3), minor: true }),
    L: (t) => (t.minor ? { root: mod12(t.root - 4), minor: false } : { root: mod12(t.root + 4), minor: true }),
  };
  export const MOVES = ['P', 'L', 'R', 'N', 'S', 'H'] as const; // order fixed, append-only
  export type Move = (typeof MOVES)[number];
  export const MOVE_STEPS: Record<Move, Step[]> = {
    P: ['P'], L: ['L'], R: ['R'],
    N: ['R', 'L', 'P'],   // R·L·P, applied left to right
    S: ['L', 'P', 'R'],
    H: ['L', 'P', 'L'],
  };
  ```
  `applyMove` folds `MOVE_STEPS`; `movePath` returns every intermediate triad. `triadName` uses `NOTE_NAMES`.
- [ ] **Step 3:** `npm test -- tonnetz` passes. Commit: `feat(tonnetz): triad model and neo-Riemannian moves`

## Task 2.2: Overlay shell

## Task 2.3: Torus geometry (pure, tested)
- `src/lib/theory/torus.ts` (no three.js): maps cell `(u,v)` and triangle (major/minor) to loop angles for a given `wraps`; small loop = `3·wraps` steps, large loop = `4·wraps` steps; copy index and "is under camera" helpers. Tests: all 24 triads appear `wraps²` times; copies share pitch class; seam positions land on copy boundaries.
- `Instanced` triangle geometry built once, one draw call per layer, with per-instance attributes for triad, copy tint and light level.

## Task 2.4: Scene and theme
- Camera inside the tube, looking along the large loop. Unlit flat colours via `ShaderMaterial`; theme tokens read from computed styles and re-read on theme change (subscribe via `lib/theme.ts`; do not copy `HarmonicsBackdrop`'s read-once pattern). Seam lines and per-copy tints. Note labels via drei SDF text, rotated about 35° counterclockwise. Colour rule: focused and selected triangles use the accent colour; everything else neutral.

## Task 2.5: Motion core
- A single motion module with two angles (large, small) plus velocity, advanced in `useFrame` with `1 − exp(−k·dt)` damping and a critically damped spring for snapping. Keys (A/D, W/S), pointer drag (pointer capture, velocity sampled over about 100 ms) and snapping all feed the same angles. No React state in the frame loop. Unit-test the integrator in isolation (frame-rate independence: 60 Hz and 120 Hz converge to the same position; snap never overshoots).

## Task 2.6: Focus, selection, arrows, moves
- **Blocked on D3.** Focus/selection model per the spec (Shift traversal never unselects; click clears; Shift-click adds; Space plays the selection via `playProgression` with `voiceTriad`). Arrow neighbours derived from geometry (see finding 6). Move bar P L R N S H with tooltips ("R – A minor"), Shift+letter shortcuts, travel along `movePath` with a GSAP timeline on the same angles, then play old → new.

## Task 2.7: Audio and glow
- Reuse `getAudioEngine()` and the store's `sound` setting; playing triangles pulse. Bloom is v3.

## Task 2.8: Reduced motion
- `prefers-reduced-motion`: no momentum or travel; steps and moves cross-fade.
